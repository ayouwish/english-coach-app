## Q1 ✅ 隐私：hybrid 部署下数据会离开家庭网络

**事实（已确认）**

- 客户端只把数据传到家庭 NAS（`english.dreamsearch.top/api`）；客户端本身不直连任何云厂商。
- 仓库 `deploy/.env` 当前为 `PROVIDER_MODE=hybrid`。按当前配置：
  - **音频** → Azure（ASR / 发音评测 / TTS）；
  - **文本** → DeepSeek（对话 / 改写 / 复述）；
  - **书页图片 / 插画提示** → DeepSeek / 智谱。
- 因此**不能**承诺音频/文本/图片留在家庭网络；这些内容会经过家庭 NAS 转发到云端。
- 服务端是否在云端留存取决于 provider 条款；客户端无法保证。家庭自用应选择不用于训练的 API/区域，并在文案中写明“可能由 NAS 转发”。

**决策**

采用 **A：如实告知**，不承诺本地处理。隐私文案写“上传到家庭 NAS，并可能由 NAS 转发给云端服务商（音频→Azure、文本→DeepSeek、图片→DeepSeek/智谱）”。这是当前部署下唯一不撒谎的写法。

| 方案 | 做法 | 状态 |
|---|---|---|
| A. 如实告知 | 文案写明会经 NAS 转云，列出数据类别 | **已采纳** |
| B. 切 local | `PROVIDER_MODE=local` + 本地模型（faster-whisper/piper/本地 LLM/本地 OCR）；关闭云 LLM/插画 | **未部署**；需要模型/GPU/时间，且能力会缩水 |
| C. 混合承诺 | 录音/评测 local，LLM/插画用云 | 仍不是“完全本地”；需后端逐项暴露 provider，暂不做 |

**需要谁拍板**：产品/家长（家庭自用即你本人）+ 部署方。
**影响**：隐私文案、上架材料、是否买 GPU/换模型、M2 能力范围。若要“完全本地”，必须先完成 B 并重新验收，当前**不具备**。

## Q2 ✅ 对话一轮：三步是现状（已核实）

**事实（代码核对）**

现有 `POST /api/chat/sessions/:id/turn`：

- **要求 `text` 非空**；
- `audio` 只用于在 `after()` 里做后台发音评估；
- 响应**只返回助手文本**，不返回 TTS 音频，也不返回发音分。

所以“只有语音输入”的移动端一轮就是三步：

```text
POST /asr → POST /chat/sessions/:id/turn(audio+text) → POST /tts
```

发音分随后由 `GET /chat/sessions/:id/messages` 的 `pron` 返回（异步，需轮询；`/sessions/:id` 没有）。

**结论**：M1 按三步实现，不再把它当待定项。`ChatService.turnByVoice()` 内部封装三步，未来后端若做一体化只换内部实现。

| 方案 | 状态 |
|---|---|
| A. 客户端三步 | **M1 采用**（现状） |
| B. 后端一体化（`/turn` 内部 ASR + 返回 TTS） | 可选优化【待后端新增】，不阻塞 M1 |
| C. 只把 ASR 收进 `/turn` | 收益有限，暂不做 |

**影响**：M1 工期、对话延迟（2–3 次请求）、错误处理复杂度。
**需要真机实测**：三步叠加后的端到端时延；不达标再评估 B。

## Q4 ✅ Bearer Token 认证（已定）

**决策**：移动端全部用 Bearer Token；**Web 端继续 Cookie**（后端双模式并存）。

```text
POST /api/auth/token    {email,password} → {access_token, refresh_token, token_type:"Bearer", expires_in:3600, user}
POST /api/auth/refresh  {refresh_token}  → 新的一对（一次性轮换）
POST /api/auth/revoke   {refresh_token}  → 204
```

- access **1h**、refresh **30d 且一次性轮换**；所有接口接受 `Authorization: Bearer <access>`。
- 客户端：access/refresh 存 **Asset Store Kit**；网络层**单飞刷新**（并发 401 只 refresh 一次，其余等待后重放）；refresh 失败 → 清 token 跳登录；退出 → `/revoke` + 清本地。
- 当前三个端点均为【待后端新增·P0】，是 M0 的阻塞依赖。
- 记录：[ADR-0002](adr/0002-bearer-token.md)（现行）；[ADR-0001](adr/0001-session-cookie.md) 已被取代。

**需要谁拍板**：后端 + 客户端（已拍板）。
**影响**：`commons/net` 认证实现、后端契约、M0 工期。

## Q6 🟠 API 20 / ArkTS 严格模式边界

**事实**：HarmonyOS NEXT 的 ArkTS 是 TypeScript 的**严格子集**，不是可选项——没有“关闭严格模式跑 TS”的开关。真正要决定的是：

1. 是否 100% 按 ArkTS 约束写（推荐）；
2. 是否为了复用 Web 代码/第三方库引入 JS/WebView（不推荐，认证/权限/隐私都不可控）；
3. 是否使用状态管理 V2、API 21+ 新特性（会增加兼容分支）。

**选项**

| 方案 | 说明 |
|---|---|
| A. 锁 API 20 + 全严格 ArkTS（推荐） | 覆盖 HarmonyOS 6.0.0；所需 HTTP/Asset/Media 能力齐全；不追 API 21+ |
| B. 追 API 21/22 | 新特性/新机型；但增加兼容分支，首版不需要 |
| C. 同时兼容 API 20 以下 | 更广；但没有收益，反而要维护降级路径，不做 |
| D. 混合 JS/WebView | 复用 Web 代码；但破坏“零三方/认证/隐私”边界，不建议 |

**建议**：A。`compileSdk/compatibleSdk/targetSdk = 20`；不使用 `@ObservedV2/@Trace`；不使用 WebView 承载业务页面。
**复核记录（2026-10-31）**：API 20 下 `@ohos.net.http` 的 `enableAutoCookie` 仍标注 `@since 26.0.0`（以本机 SDK d.ts 为准【待确认】）；但本方案已改 Token，**不需要也不依赖**它。Asset Store Kit 的 `add/query/remove` 及同步版本在 API 20 均可用；`SECRET` 单条上限【待确认】。
**影响**：可用 API、测试机型、未来升级成本、可复用的 Web 代码量。

## Q7 🟠 本人修改密码 + 注销全部会话

**现状**

- 只有 `POST /family/members/:id/password`（仅家长，管理员重置）。
- 重置只改 `password_hash`，**不吊销现有 refresh token**；旧设备在 refresh 到期/被 revoke 前仍有效。
- `/auth/revoke` 只能吊销**当前这一个** refresh token；没有“注销全部设备”。

**选项**

| 方案 | 需要 |
|---|---|
| A. 维持现状 + 文案提示（推荐短期） | 无后端改动；提示“旧设备可能仍登录” |
| B. 新增 `POST /auth/password` | 旧密码 + 新密码；儿童也可自助 |
| C. 新增 `POST /auth/logout-all` | 吊销该用户所有 refresh token；重置密码时可选调用 |

**建议**：M3 前做 B/C（如果上架/安全要求）；否则 A + 明确提示。
**影响**：账号安全、上架合规、后端工作量。

## Q8 🟠 数据保留期与用户删除入口

**现状**

- 登录态（refresh token）30 天；录音/评测/聊天无自动过期（以实际代码为准）。
- 有运维脚本 `cleanup-user-data.mjs`（按账号+时间点，删前备份），**不是 App 功能**。
- App 内没有“删除我的数据/账号”。

**选项**

1. 产品提供“联系家长/管理员删除”流程（推荐短期）。
2. 后端新增 `DELETE /me/data`（按时间范围/全部），家长可代孩子执行。
3. 自动保留期（如录音 90 天），后台清理。

**建议**：上架前至少做 1；有精力做 2。
**影响**：合规、存储体积、家长信任。

## Q9 🟠 域名/证书/内网可达性

**现状**

- `https://english.dreamsearch.top` 只在家庭网络/VPN 内可达。
- 依赖家庭 DNS/反代/Caddy 证书。

**需确认**

**影响**：登录成功率、支持成本。

## Q11 🟡 音色选择开放程度

**影响**：设置页复杂度、TTS 失败率。
